# 경희대 AMP 총동문회 앱 — 영업용 모바일 웹 데모 설계

> 작성일: 2026-07-22
> 근거 문서: `원우회앱_기능정의서.md` (현행 앱 화면 캡처 20장 분석본)
> 산출물 위치: `amp/` (본 리포지토리)

---

## 1. 목적과 성격

경희대학교 테크노경영대학원 AMP과정 총동문회에 제안할 **영업용 프로토타입**이다. 실제 서비스가 아니며 백엔드가 없다. 목데이터 위에서 화면과 사용자 플로우를 실제로 조작할 수 있게 만들어, 현행 앱 대비 개선안을 시연하는 것이 유일한 목적이다.

성공 기준:

1. 노트북 또는 아이폰에서 링크 하나로 즉시 실행된다. 설치·빌드·로그인 서버가 필요 없다.
2. 8개 코어 화면을 실제로 눌러가며 끊김 없이 시연할 수 있다.
3. 기능정의서의 전체 메뉴 구조(IA)가 화면 어딘가에서 전부 확인된다.
4. 현행 앱 대비 개선 포인트(가독성·터치 타깃·정보 위계)를 말로 설명하지 않아도 보인다.

명시적 비목표: 회원가입·인증, 실데이터 연동, 관리자 도구, 푸시 알림, 접근성 인증 수준의 대응, 자동화 테스트.

## 2. 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 결과물 | 영업용 프로토타입/데모 | 실서비스 구축 전 제안 단계 |
| 구현 형태 | 정적 HTML + Tailwind CDN, 빌드 없음 | 기존 리포 스택과 동일, GitHub Pages 직배포 |
| 구조 | `amp/` 폴더 + ES 모듈, 화면당 1파일 | 화면 교체가 잦은 영업 데모 특성 |
| 디자인 | 모던 리디자인 | 현행 앱 재현은 영업 임팩트가 없음 |
| 데이터 | 가상 인물 + 실제 조직명 | 현실감 확보, 개인정보 리스크 제거 |
| 화면 범위 | 코어 8개를 상세 화면까지 깊게 | 시연 동선을 선명하게 유지 |

## 3. 화면 정의

### 3.1 코어 8개

**1. 로그인 (`#/login`)**
앱 로고, 기수 선택 드롭다운, 아이디·비밀번호 입력, 로그인 버튼. "데모 계정으로 시작" 버튼을 두어 시연 시 입력을 건너뛴다. 로그인 성공은 무조건 홈으로 이동한다(검증 없음).

**2. 홈 (`#/home`)**
위에서부터: 통합 검색바 → 행사 배너(캐러셀) → 대형 퀵버튼 2종(원우수첩·사업장소개) → 아이콘 퀵메뉴 5종(회장 인사말씀·동문 조직도·사업계획 일정표·산하단체·대학원 소개) → 게시판 탭 위젯(공지사항·동문경조사·동문회활동, 탭당 최신 3건) → 동문기업 광고 배너 → 전체 게시물 최신 목록.

**3. 원우수첩 (`#/directory`, `#/directory/:gen`, `#/member/:id`)**
- 기수 그리드: 1~62기를 원형 버튼 그리드로. 기수별 인원 수를 함께 표시한다.
- 명부 목록: 상단 기수 탭(가로 스크롤), 회원 검색, 분류 필터, 정렬 드롭다운, 목록/지도 보기 토글. 회원 행에는 프로필 사진, 이름, 회사·직함, 기수, 사업장 주소, 전화걸기 버튼이 들어간다.
- 회원 상세: 프로필 헤더, 소속·기수, 사업장 정보와 약도, 전화걸기·쪽지보내기 액션.

**4. 사업장소개 (`#/biz`, `#/biz/:category`, `#/biz/detail/:id`)**
업종 카테고리 8종(외식업 / 가구·가전·건설 / 제조업·반도체 / 골프·유통 / 병원·의료 / 자동차 / 여행·서비스 / 교육·학원) → 업종별 사업장 목록 → 사업장 상세(대표 동문, 기수, 소개, 주소, 전화).

**5. 게시판 (`#/board/:type`, `#/post/:id`)**
공지사항·동문경조사·동문회활동 3개 탭. 목록에는 [공지] 라벨, 제목, 작성자, 작성일, 조회수, 댓글 수 뱃지, 검색바, 글쓰기 FAB. 상세에는 본문과 댓글 목록·입력창.

**6. 갤러리 (`#/gallery`, `#/gallery/:albumId`)**
총동문회갤러리·회원갤러리 탭, 앨범 카드 → 사진 그리드 → 탭 시 라이트박스.

**7. 행사일정표 (`#/schedule`)**
연간 사업계획을 월별 타임라인 카드로 재구성한다. 원본은 일자/행사명/행사내용/대상/장소 5열 표이며, 모바일에서 표는 읽히지 않으므로 카드로 전환한다. 지난 일정은 흐리게, 다가오는 일정은 강조. 하단에 "계획안은 변경될 수 있습니다" 고지를 유지한다.

**8. 설정/내정보 (`#/settings`, `#/profile/edit`)**
프로필 헤더(사진·닉네임·기수), 메뉴 목록(정보수정, 알림, 쪽지, 사무국 전화, 사무국 오는 길, 로그아웃, 회원탈퇴). 정보수정 화면에는 이메일·비밀번호·휴대폰·이름·닉네임·기수·메일 수신동의 체크박스·수정 버튼을 둔다. 저장은 토스트만 띄우고 실제 반영은 하지 않는다.

### 3.2 전역 셸

- **헤더**: 뒤로가기(홈이 아닐 때), 화면 타이틀, 햄버거 버튼.
- **하단 탭바**: 홈 / 전체 게시글 / 알림 / 설정. 항상 고정.
  - **전체 게시글(`#/board/all`)**: 게시판 화면의 한 종류로 처리한다. 3개 게시판의 글을 작성일 내림차순으로 합쳐 보여주며, 각 행에 출처 게시판 뱃지를 붙인다. 탭 헤더 대신 통합 목록만 노출한다.
  - **알림(`#/alerts`)**: 새 글·댓글·쪽지 알림 목록. 항목을 누르면 해당 글이나 쪽지로 이동한다. 읽음/안읽음 상태를 시각적으로 구분한다.
  - **쪽지(`#/messages`)**: 설정 화면과 알림에서 진입한다. 대화 상대 목록 → 1:1 대화 화면. 전송은 화면에만 말풍선을 추가하고 데이터는 바꾸지 않는다.
- **전체메뉴 드로어**: 기능정의서 GNB의 모든 항목을 계층 그대로 노출한다 — 회장인사말씀, 동문조직도, 정관, 원우수첩, 산하단체(T.K산악회·테경회·여성회 각각 인사말/조직도/갤러리/일정표/공지사항), 대학원소개, 사업계획 및 행사일정표, 갤러리, 커뮤니티, 총동문회 홈페이지, 사업장소개.

코어 8개 밖의 항목을 누르면 "준비 중입니다" 바텀시트가 뜬다. IA 전체가 설계돼 있음을 보여주면서 구현 범위는 통제하기 위한 장치다.

## 4. 아키텍처

```
amp/
├─ index.html      셸 — 헤더 · 하단탭바 · #view · 드로어 · 폰 프레임
├─ app.js          해시 라우터, 화면 마운트·전환, 드로어/토스트 제어
├─ data.js         목데이터 단일 소스
├─ ui.js           공통 컴포넌트 팩토리
└─ screens/
   ├─ login.js  home.js  directory.js  member.js  biz.js
   ├─ board.js  post.js  gallery.js  schedule.js  settings.js
   └─ alerts.js  messages.js
```

`board.js`는 `type` 파라미터로 공지사항·동문경조사·동문회활동·전체(`all`) 네 경우를 모두 처리한다. `settings.js`는 설정 목록과 정보수정 폼(`#/profile/edit`)을 함께 담당한다.

**모듈 경계**

- `screens/*.js`는 각각 `render(params) → HTMLElement` 하나만 export한다. 화면 모듈끼리는 서로 import하지 않는다.
- 화면 간 이동은 오직 `location.hash` 변경으로 이루어진다. 화면은 다른 화면의 존재를 모른다.
- `data.js`는 순수 데이터만 담고 DOM을 모르며 아무것도 import하지 않는다.
- `ui.js`는 데이터를 모르고, 전달받은 인자만으로 엘리먼트를 만든다.

이 경계 덕분에 화면 하나를 통째로 다시 써도 나머지가 깨지지 않고, 고객사가 바뀌면 `data.js`만 교체하면 된다.

**라우팅**

`app.js`가 `hashchange`를 듣고 `#/name/param` 패턴을 파싱해 해당 화면의 `render`를 호출한 뒤 `#view`의 내용을 교체한다. 매칭되는 라우트가 없으면 "준비 중" 시트를 띄우고 직전 화면을 유지한다. 화면 전환에는 짧은 슬라이드 트랜지션을 건다.

**상태**

로그인 여부와 현재 사용자만 `app.js`의 모듈 스코프 변수로 들고 있다. 영속화하지 않으며 새로고침하면 로그인 화면으로 돌아간다. 데모에서는 이 편이 오히려 시연 시작점이 일정해 유리하다.

## 5. 디자인 시스템

**컬러**: 프라이머리는 경희 크림슨 `#8B0029`, 진한 상태 `#6E0020`, 옅은 배경 `#FCF2F4`. 텍스트는 `#1A1A1E` / `#5A5A66` / `#9A9AA6`. 배경은 `#FFFFFF`, 섹션 구분 배경 `#F5F5F7`. 강조 보조색은 골드 `#B8893A`(행사·기수 뱃지).

**타이포**: Pretendard. 본문 16px, 목록 제목 17px, 화면 타이틀 20px, 캡션 13px. 굵기는 400/600/800만 사용한다.

**레이아웃**: 카드 radius 16px, 그림자는 `0 2px 8px rgba(0,0,0,.06)` 한 종류만. 화면 좌우 여백 20px. 리스트 행 높이 최소 64px.

**터치 타깃**: 모든 탭 가능 요소는 최소 48×48px. 전화걸기 등 핵심 액션은 아이콘 단독이 아니라 라벨을 동반한 버튼으로 만든다.

대상 사용자가 40~70대 동문이라는 점이 이 시스템의 근거다. 현행 앱 대비 가장 체감되는 차이가 여기서 나오므로, 영업 시연의 핵심 설명 포인트이기도 하다.

**반응형**: 뷰포트 폭 480px 초과 시 콘텐츠를 폭 390px의 폰 목업 프레임 안에 렌더하고 주변을 어둡게 처리한다. 480px 이하에서는 프레임 없이 풀스크린. 노트북 시연과 실기기 시연을 모두 자연스럽게 만든다.

## 6. 목데이터

`data.js`가 담는 것:

- **회원 약 60명**: 대표 기수 6개(45·49·55·58·60·62기)에 분산. 이름·회사·직함·휴대폰·사업장 주소는 전부 가상. 기수 그리드의 1~62기는 전부 표시하되 데이터가 없는 기수는 인원 0으로 두고 빈 상태 UI를 보여준다.
- **사업장 24곳**: 8개 업종에 3곳씩.
- **게시글 30여 건**: 공지사항 12, 동문경조사 8, 동문회활동 10. 각각 작성자·작성일·조회수·댓글 수와 본문, 댓글 2~4개.
- **갤러리 앨범 4개**: 앨범당 사진 6~12장.
- **연간 일정 20여 건**: 신년하례회, 정기월례회, 산행, 골프대회, 명사특강, 입학식·졸업식, 워크샵, 봉사활동 등.
- **알림 8건, 쪽지 5건.**

동문회·기수·동호회(T.K산악회·테경회·여성회)·사무국 주소와 전화번호는 기능정의서 그대로 사용한다. 인물과 기업 정보는 전부 가상이며, 실존 인물과 무관함을 데이터 파일 상단 주석에 명시한다.

**이미지**: 외부 이미지 서비스를 호출하지 않는다. 리포에 이미 있는 이미지와 CSS 그라디언트 플레이스홀더(이니셜 표시)로 처리한다. 오프라인에서도 시연이 깨지지 않아야 하기 때문이다.

## 7. 동작과 예외 처리

실제로 동작해야 하는 것: 기수·업종·게시판 탭 전환, 회원 검색과 필터·정렬, 게시글 검색, 갤러리 라이트박스, 폼 입력, 전화걸기(`tel:` 링크), 화면 간 이동과 뒤로가기.

흉내만 내는 것: 지도 보기(정적 지도 이미지 + 핀 오버레이), 글쓰기·댓글 등록·정보 저장(토스트만 표시), 로그인 인증.

예외 처리:

| 상황 | 처리 |
|---|---|
| 미구현 라우트 | "준비 중입니다" 바텀시트, 현재 화면 유지 |
| 검색·필터 결과 0건 | 빈 상태 일러스트 + 안내 문구 + 필터 초기화 버튼 |
| 데이터 없는 기수 | 빈 상태 UI |
| 이미지 로드 실패 | 이니셜 그라디언트 플레이스홀더로 대체 |
| 저장·등록 액션 | 토스트로 완료 표시, 데이터는 변경하지 않음 |

## 8. 검증

자동화 테스트는 만들지 않는다. 데모의 산출물은 화면이고, 검증 대상도 화면이다. 대신 구현 후 브라우저 프리뷰로 다음을 직접 확인한다.

1. 8개 코어 화면과 하위 상세 화면까지 실제 클릭으로 이동 — 로그인 → 홈 → 원우수첩 → 기수 → 명부 → 회원 상세 → 뒤로 → 사업장 → 게시판 → 글 상세 → 갤러리 → 일정표 → 설정 전 구간.
2. 콘솔 에러 0건, 네트워크 404 0건.
3. 375px(iPhone SE)과 430px(iPhone Pro Max) 두 폭에서 가로 스크롤이 발생하지 않음.
4. 데스크톱 폭에서 폰 프레임이 정상 렌더됨.
5. 검색·필터·탭·라이트박스가 실제로 반응함.

확인 후 주요 화면 스크린샷을 사용자에게 제시한다.

## 9. 배포

기존 GitHub Pages 설정을 그대로 사용한다. 별도 워크플로 변경 없이 `main` 푸시로 배포되며 접근 주소는 다음과 같다.

```
https://dyiot36524-prog.github.io/gsltHomePage/amp/
```

GSLT 홈페이지 본문에서 이 데모로 링크를 걸지는 이번 범위에 포함하지 않는다. 영업 담당자가 URL을 직접 전달하는 것을 전제한다.
